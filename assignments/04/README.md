# 第4回課題：時間変化を利用したオリジナルアニメーション

## 1．課題の目的

Processingを用いて，時間の経過によって図形の状態が変化するオリジナルアニメーションを制作してください．

この課題では，以下の内容を確認します．

- `setup()` と `draw()` の役割を理解している
- Frameごとに状態を更新してアニメーションを作れる
- 位置と速度を変数として扱える
- 条件分岐によって画面端などで状態を変更できる
- 位置以外のパラメータも時間によって変化させられる

授業では，アニメーションを「状態を時間とともに更新して描画すること」と整理しています．

---

## 2．課題内容

Processingを用いて，**1つ以上の図形が時間とともに変化するアニメーション**を制作してください．

テーマは自由です．例えば，次のような表現が考えられます．

- 画面内を移動する物体
- 光が移動する表現
- 波紋が広がる表現
- 円が上下に揺れる表現
- 大きさや色が周期的に変化する表現
- 画面端から反対側へ現れる物体
- ランダムな位置や色を利用した表現

ただし，授業資料の例題をそのまま提出するのではなく，図形，動き，色，変化の規則などを変更して，自分の作品として制作してください．

## 3．必須条件

以下の条件をすべて満たしてください．

### 3-1．`setup()` と `draw()` を使用する

```processing
void setup() {
  size(600, 600);
}

void draw() {
  // 描画処理
}
```

`setup()` は開始時に1回だけ実行され，`draw()` はプログラムの実行中に繰り返されます．

### 3-2．時間によって変化する変数を2つ以上使用する

例：

```processing
float x;
float xSpeed;
float circleSize;
```

対象は，以下のようなものとします．

- 位置
- 大きさ
- 色
- 透明度
- その他の図形パラメータ

### 3-3．図形の位置をFrameごとに更新する

速度を表す変数を1つ以上用意し，図形を移動させてください．

例：

```processing
x = x + xSpeed;
```

授業では，この更新を次の漸化式として扱っています．

```text
x_(n+1) = x_n + v
```

### 3-4．画面端に対する処理を実装する

`if` 文を用いて，図形が画面端に到達した場合の処理を実装してください．

例えば，

- 反対側に戻す
- 移動方向を反転する
- 新しい位置に移動する
- 大きさや色を変更する

などです．

例：

```processing
if (x > width) {
  x = 0;
}
```

### 3-5．位置以外のパラメータを1つ以上時間変化させる

以下から1つ以上を変化させてください．

- 大きさ
- 色
- 透明度
- 形状

例えば，

```processing
circleSize = circleSize + 2;
```

のような処理です．

### 3-6．状態をリセットまたは変化させる処理を1つ以上作る

ある値が一定値を超えた場合に，

```processing
if (circleSize > 300) {
  circleSize = 1;
}
```

のように状態を変更してください．

このような値は授業資料では **Threshold（閾値）** として扱っています．

### 3-7．色を使用する

以下を利用して，作品に色を付けてください．

```processing
background();
fill();
stroke();
noStroke();
```

のいずれかを適切に組み合わせてください．

### 3-8．コードにコメントを書く

主な処理について，

```processing
// 円の位置を更新
x = x + xSpeed;
```

のようにコメントを記述してください．

## 4．推奨する基本構造

以下は考え方の例です．そのまま提出するのではなく，各自で改造してください．

```processing
float x;
float y;
float xSpeed;
float circleSize;

void setup() {
  size(600, 400);

  x = 0;
  y = height / 2;

  xSpeed = 3;
  circleSize = 30;

  noStroke();
}

void draw() {
  background(255);

  fill(50, 120, 255);
  ellipse(x, y, circleSize, circleSize);

  // 位置を更新
  x = x + xSpeed;

  // 大きさを更新
  circleSize = circleSize + 0.2;

  // 右端を超えたら左へ戻る
  if (x > width) {
    x = 0;
  }

  // 大きくなりすぎたらリセット
  if (circleSize > 100) {
    circleSize = 30;
  }
}
```

重要なのは，

```text
描画 → 状態の更新 → 条件判定 → 次のFrame
```

という流れを理解することです．

## 5．発展課題

余裕がある場合は，以下のいずれかを追加してください．

### 発展1：`sin()` による周期運動

`sin()` を用いて，図形を滑らかに往復させてください．

```processing
float y = height / 2
        + 100 * sin(frameCount * 0.05);
```

### 発展2：`random()` の利用

位置，色，大きさなどの一部をランダムにしてください．

```processing
x = random(width);
y = random(height);
```

ただし，作品全体を完全なランダムだけで構成せず，規則的な時間変化と組み合わせてください．

### 発展3：軌跡を利用する

`draw()` 内の `background()` を削除する，または透明度を利用して，過去のFrameを画面に残してください．

`background()` を毎Frame実行しない場合，過去の描画結果が残り，軌跡のような表現になります．

### 発展4：複数の動きを組み合わせる

例えば，

- x方向に一定速度運動
- y方向に `sin()` による周期運動
- 大きさを時間変化
- 色を時間変化

などを組み合わせてください．

## 8．減点の目安

以下は採点時の減点目安です．複数の不備が重複する場合は，内容を確認した上で総合的に判断します．

|                       不備                       | 減点目安 |
| ------------------------------------------------ | -------: |
| 実行時エラーでアニメーションを確認できない       | -3〜-5点 |
| `setup()` または `draw()` が適切に使われていない | -1〜-2点 |
| 図形が動かない                                   |     -2点 |
| 速度を変数として扱っていない                     |     -1点 |
| 画面端または閾値による状態変更がない             |     -2点 |
| 位置以外のパラメータ変化がない                   |     -2点 |
| 実質的に静止画になっている                       | -3点以上 |
| コメントがない                                   |     -1点 |
| 提出形式・ファイル名に不備がある                 |     -1点 |
| 授業の例題をほぼそのまま提出している             | -2点以上 |

### 減点に関する補足

#### 実行時エラー

提出されたスケッチが実行できない場合，アニメーションの動作を確認できないため，大きく減点します．ただし，単純な記述ミスで容易に修正可能な場合は，実装内容を確認した上で減点幅を調整します．

#### 図形が動かない場合

今回の課題では，Frameごとの状態更新が主要な学習目標です．そのため，実行しても図形の位置が変化しない場合は，移動アニメーションの項目を原則として評価しません．

#### 画面端・閾値処理

画面端または一定値に達したときの状態変更は，今回の必須条件です．単純な移動のみで状態遷移がない場合は，該当項目を減点します．

#### 位置以外のパラメータ変化

位置だけでなく，大きさ，色，透明度，形状などの時間変化を実装していることを確認します．位置変化のみの場合は減点対象です．

## 教員用メモ

### この課題で確認したいこと

第4回では，静止画からアニメーションへ移行し，次の考え方を理解できているかを確認します．

```text
現在の状態
   ↓
描画
   ↓
状態を更新
   ↓
条件判定
   ↓
次のFrame
```

特に重視するのは，**Frameごとに状態変数を更新することでアニメーションが成立すること**を理解しているかどうかです．

### 最低到達ライン

以下を満たしていれば，基本的な到達目標は達成したと判断します．

- Processing上で正常に実行できる
- `setup()` と `draw()` を使用している
- 位置と速度を変数として扱っている
- Frameごとに位置を更新している
- `if` 文による画面端または閾値処理がある
- 位置以外のパラメータを1つ以上時間変化させている
- コメントが記述されている
- 指定された形式で提出されている

### 高評価につながる要素

以下は必須ではありませんが，作品の完成度を判断する際の参考とします．

- `sin()` / `cos()` を利用した周期運動
- `random()` と規則的な時間変化の組み合わせ
- 透明度を利用した軌跡表現
- 複数の図形や複数種類の動きを組み合わせている
- Frame Rateや速度を意識した設計
- 状態変数や定数が整理され，可読性が高い
- 条件式や数式が視覚表現に効果的に反映されている

### 採点時の優先順位

作品性については主観が入りやすいため，基本的には次の順序で評価します．

1. 授業で扱った技術を正しく実装できているか
2. 必須条件を満たしているか
3. コードが意図どおりに動作しているか
4. アニメーションとしてまとまりがあるか

見た目が高度であっても，時間更新や状態遷移などの技術的要件を満たしていない場合は，高得点とはしません．
